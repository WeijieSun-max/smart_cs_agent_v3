# 套餐推荐策略 V1

## 1. 分析窗口

优先使用最近 3 个完整账期，并结合当前账期预测值：

- 完整账期少于 1 个：数据不足，不给出确定性“最优套餐”；可以展示当前套餐和候选套餐差异，并询问用户通常的流量、通话需求。
- 只有 1 个完整账期：标记 `low_confidence`，建议偏保守，明确样本有限。
- 有 2～3 个完整账期：标记 `normal_confidence`。
- 当前账期已过至少 7 天时，可以使用工具返回的月度预测；不足 7 天只作为早期观察，不放大为整月事实。

工具负责聚合和计算账期统计，Skill 不自行猜测缺失数据。

## 2. 需求估计

以工具返回的 usage profile 为准。默认策略：

- 数据需求参考最近完整账期的较高使用水平和当前月预测，并保留约 15% 缓冲；
- 语音需求参考最近完整账期的较高使用水平和当前月预测，并保留约 10% 缓冲；
- 最近发生多次流量补充或超额费用时，提高数据容量稳定性的优先级；
- 使用量明显下降但只有一个月样本时，不立刻推荐大幅降档；
- 无限量或封顶规则只能使用 plan tool 返回的结构化字段，不能从套餐名称推断。

具体 percentile、预测和预计费用由 `telecom_compare_plans` 确定性计算并返回，避免模型自行做金额运算。

## 3. 候选过滤

排除：

- 非 active 或不在生效期内的套餐；
- 当前线路不具备资格的套餐；
- 数据或语音容量明显低于估计需求且预计产生高额超量费用的套餐；
- 价格和容量都被另一候选完全支配的套餐；
- 工具标记为不可比较、价格未知或规则不完整的套餐。

不得因为候选数量不足而编造套餐。

## 4. 排序原则

按以下优先级选择主推荐：

1. 满足预计数据和语音需求；
2. 预计月总成本较低，包括月租和预计超量/补充费用；
3. 有合理容量缓冲，降低频繁补流量的概率；
4. 相比当前套餐具有明确收益；
5. 变更收益接近时，优先保持当前套餐，避免无意义切换。

“明确收益”的首版默认判断：候选预计月总成本至少降低 10%，或在成本增加不超过 10% 时解决持续的流量/语音不足。该阈值属于策略配置，后续可版本化调整。

## 5. 推荐数量

- 1 个主推荐；
- 最多 2 个真正体现不同取舍的备选，例如“最低预计成本”和“更多容量缓冲”；
- 当前套餐最合适时，主推荐是“保持不变”，无需为了凑数推荐变更。

## 6. 回复必须披露

- 使用了哪些账期，数据质量如何；
- 最近流量和通话的大致使用水平；
- 当前套餐与推荐套餐的月租/预计总成本差异；
- 推荐原因和主要取舍；
- 推荐不等于已经变更；
- 价格和资格以执行变更前的最新查询为准。

## 7. 不可靠数据

出现以下情况时不下确定性结论：

- usage、当前套餐或候选计划读取失败；
- 账期数据明显冲突；
- 套餐价格/容量字段缺失；
- 没有任何 eligible candidate；
- 用户没有明确目标线路。

此时提出最少量的澄清问题或告知稍后重试，不用模型常识补齐业务事实。
